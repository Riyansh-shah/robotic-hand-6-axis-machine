Chapter 03 — Mathematical Core

Kinematics

The mathematical engine of the robot — mapping between Cartesian space (where the nozzle must go) and joint space (what each motor must do). Covers DH parameters, forward kinematics transformation chains, and the analytical inverse kinematics solution exploiting the spherical wrist.

Denavit-Hartenberg Parameters

The Modified DH convention (Craig, 1986) is used. Each joint is described by four parameters: a (link length), α (link twist), d (link offset), and θ (joint angle — the variable). The table below defines the kinematic skeleton of the arm.

Joint i θᵢ (variable) dᵢ (mm) aᵢ (mm) αᵢ (rad)
1 (Waist) θ₁ 120 0 π/2
2 (Shoulder) θ₂ 0 210 0
3 (Elbow) θ₃ 0 20 π/2
4 (Forearm Roll) θ₄ 185 0 −π/2
5 (Wrist Pitch) θ₅ 0 0 π/2
6 (Tool Roll) θ₆ 50 0 0

Forward Kinematics

Joint angles → TCP pose

Each joint transformation is a 4×4 homogeneous matrix ᵢ₋₁Aᵢ encoding both rotation and translation. The full Forward Kinematics solution is the product of all six individual joint matrices:

⁰T₆ = ⁰A₁ · ¹A₂ · ²A₃ · ³A₄ · ⁴A₅ · ⁵A₆

Each Aᵢ has the form:
[ cos(θ) -sin(θ)cos(α) sin(θ)sin(α) a·cos(θ) ]
[ sin(θ) cos(θ)cos(α) -cos(θ)sin(α) a·sin(θ) ]
[ 0 sin(α) cos(α) d ]
[ 0 0 0 1 ]

The resulting ⁰T₆ matrix encodes the complete pose of the tool-center-point (TCP) — the top-left 3×3 block is the rotation matrix R (nozzle orientation), and the rightmost 3×1 column is the position vector p = [px, py, pz]ᵀ.

⁰T₆ = [ R | p ]
        [----+---]
        [ 0 | 1 ]

R ∈ SO(3) — nozzle orientation
p ∈ ℝ³ — nozzle position (mm)

FK Computation Cost

Forward kinematics is computationally cheap — a single matrix chain multiply. At 1000 Hz control rate, computing FK takes <0.1ms on an STM32F4 (168 MHz ARM Cortex-M4), leaving ample budget for PID and communication.

Inverse Kinematics — Analytical Decoupled Solution

Because the wrist is spherical (J4/J5/J6 axes intersect), the IK problem decouples cleanly into a position sub-problem (find J1–J3 to reach the wrist center) and an orientation sub-problem (find J4–J6 to orient the nozzle). This avoids iterative Jacobian methods and gives a closed-form, real-time solution.

Step 1 — Wrist Center Location

Given desired TCP pose (p, R), compute wrist center Wc by backing off along the approach axis by the wrist-to-TCP offset d₆:

Wc = p − d₆ · R[:,2]

where R[:,2] is the z-column
of the desired orientation R

Step 2 — Solve J1, J2, J3

With Wc known, use geometry of the planar 2-link arm (shoulder+elbow) to solve the positioning joints:

θ₁ = atan2(Wcy, Wcx)

r = √(Wcx²+Wcy²) − a₁
s = Wcz − d₁
D = (r²+s²−a₂²−a₃²)/(2·a₂·a₃)
θ₃ = atan2(±√(1−D²), D)
θ₂ = atan2(s,r) − atan2(a₃·sin(θ₃), a₂+a₃·cos(θ₃))

Step 3 — Solve J4, J5, J6 (Euler ZYZ Extraction)

With J1–J3 known, compute the wrist-relative rotation ⁰R₃ᵀ · R = ³R₆. Extract the ZYZ Euler angles from this matrix to get θ₄, θ₅, θ₆:

³R₆ = ⁰R₃ᵀ · R_desired

θ₅ = atan2( √(R₃₆[0,2]²+R₃₆[1,2]²), R₃₆[2,2] )
θ₄ = atan2( R₃₆[1,2]/sin(θ₅), R₃₆[0,2]/sin(θ₅) )
θ₆ = atan2( R₃₆[2,1]/sin(θ₅), -R₃₆[2,0]/sin(θ₅) )

Analytical IK — Our Approach

Real-time capable — solution in <1ms on microcontroller

Deterministic — always returns the same solution for a given pose

Up to 8 solutions (elbow up/down × shoulder flip × wrist flip); we pick the nearest-to-current configuration

Requires spherical wrist — not general for all arm geometries

Numerical IK — Fallback

Works for any arm geometry, no special structure required

Handles redundancy and joint limits naturally

Jacobian inversion is slow (~10ms) and may not converge near singularities

Requires initial guess; wrong guess → wrong local minimum
