Chapter 06 — Electronics & Firmware

Control System

The hardware and firmware stack that translates planned joint trajectories into precise stepper pulses and servo commands in real time — coordinating 6+ axes simultaneously while managing temperature, fans, and safety limits.

Hardware Architecture

Host Computer

Raspberry Pi 4 (4GB) running a Python-based motion server. Handles G-code parsing, IK solving, trajectory generation, and trajectory streaming to the motion controller over USB serial at 250,000 baud. OctoPrint provides the web interface for job management.

Motion Controller

Arduino Mega 2560 running a modified Marlin 2.x firmware. Receives pre-computed absolute joint angles from the host and executes precise step/direction pulses for the 5 stepper axes plus PWM control for J6 servo. Step rate up to 40 kHz per axis via hardware timers.

Stepper Drivers

TMC2208 drivers in UART mode for J1–J5. Silent StealthChop mode for low-speed precision; SpreadCycle mode for high-speed travel. Current set to 1.2A RMS for J1–J3 (NEMA 17), 0.8A RMS for J4–J5 (NEMA 14). Sensorless homing via StallGuard2.

Power Supply

24V / 20A switching PSU (480W). 24V rail for stepper drivers and heated bed; 12V step-down for Raspberry Pi and fan rail; 5V for servo and logic. All rails fused independently.

Safety Features

Hardware joint limit switches on J1–J3. Thermal runaway detection on hotend and bed. Watchdog timer resets controller if host communication drops for >500ms — printer pauses gracefully.

Firmware & Software Stack

Marlin 2.1 (Modified) — Low-Level Firmware

Standard Marlin modified to accept absolute joint angles rather than Cartesian coordinates. The kinematic transform module is replaced with a passthrough — Marlin sees each joint as an independent linear axis. Stepper stepping and thermal management remain unchanged from stock Marlin.

Python Motion Server — Mid-Level

Runs on Raspberry Pi. Modules: gcode_parser.py (lexer + G1 extractor), ik_solver.py (analytical IK), trajectory_gen.py (spline fitting, velocity profiling), stream_controller.py (serial framing, flow control). Written in Python with NumPy for matrix math.

OctoPrint + Custom Plugin — High-Level UI

OctoPrint handles job queueing, webcam monitoring, and temperature graphs. A custom plugin intercepts uploaded G-code files, passes them through the motion server pipeline, and substitutes the processed joint-angle command stream before sending to Marlin.

PID Tuning — Joint Position Control

Since stepper motors operate open-loop (no encoder feedback), "PID tuning" here refers to the hotend and heated-bed temperature controllers. Joint position accuracy is achieved through step counting + mechanical repeatability. Future closed-loop work with encoders is discussed in Chapter 12.

6-Axis Synchronization

Marlin's stepper ISR uses a Bresenham-like stepping algorithm to synchronize all six axes. All joints reach their commanded positions at exactly the same time step, even when they move by very different angular amounts — critical for maintaining the correct TCP trajectory.

ISR rate: 40 kHz (25μs period)
Worst-case jitter: <5μs
Position error: <1 microstep

Communication Protocol

The Raspberry Pi streams pre-computed joint angle commands to Marlin using a custom binary framing protocol over USB serial. Each frame is 32 bytes: 6 × 4-byte floats (joint angles) + 1 × 4-byte float (extrusion amount) + 4 bytes header/checksum. At 250k baud, this allows 600+ frames/second — far exceeding the 1kHz control requirement.

Frame: [0xAA][θ₁..θ₆][E][CRC]
Size: 32 bytes / frame
Rate: up to 625 frames/s
